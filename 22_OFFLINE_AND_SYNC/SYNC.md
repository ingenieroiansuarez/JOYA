# Offline and synchronization protocol
Local SQLite tables projects, cached_revisions, families, rate_snapshots, outbox_operations, inbox_cursor, job_cache, assigned_tasks. Encrypt sensitive fields/cache where required; tokens in platform secure storage. Guest designs local only, claim after OIDC using nonce; do not upload without consent. Each operation has UUID, deviceId, projectId, branch, baseRevisionId, logical sequence, operationType, payload, createdAt, status (PENDING/SENT/APPLIED/CONFLICT/REJECTED). Persist in same local TX as local change. Retry network with exponential backoff/jitter, connectivity and foreground trigger; WorkManager best effort (OS may defer). Client never claims remote success before ACK. Push ordered per project/branch; server dedups by op ID and body hash; checks actor and base revision; response per op and cursor. Pull paginated ordered events by opaque cursor and ACL; full resync if cursor expired; preserve pending operations. Assets fetched by hash, resume and validate, LRU eviction except unsynced drafts. Sign-out clears or locks private cache; no deletion of pending drafts without user confirmation.

Conflict: changes on independent stable parameters can merge if invariant and dependencies still valid; otherwise create conflict branch, show local vs remote, allow rebase/choose/duplicate, retain both. Never use timestamp last-write-wins for CAD, money, inventory or custody. Payments, quotes acceptance, gem reserve and custody transfer authoritative online; offline workshop time/evidence append only, supervisor reconciliation. Cached price timestamp and currency visible, invalid after TTL; final quote server only. Tests: app killed before send/after commit before ACK, network flap, duplicate event, device clock skew, revoked permission, old schema, same component edit, partial upload, storage full, restore. No lost acknowledged operation, no duplicate side effect.

Contrato (1.5.0): `SyncOperation` en OpenAPI; `operation` es un `DesignOperation` (misma lista permitida que en línea). La respuesta trae un resultado por operación: APPLIED, CONFLICT o REJECTED.
