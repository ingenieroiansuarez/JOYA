# Seguridad y privacidad
Threat model: cliente malicioso (IDOR, cambio precio, replay), empleado (abuso stock y acceso), proveedor externo (archivo malicioso), LLM (prompt injection/tool abuse), atacante red (tokens/webhooks), dispositivo perdido (cache), insider infra (secretos), fraude/chargeback. Trust boundaries: cliente→API, API→DB, worker→object, provider→webhook, staff→resource. Fail closed.

OIDC Authorization Code + PKCE mobile; web BFF/session cookie Secure HttpOnly SameSite + CSRF where relevant; validate issuer, audience, expiry, revocation; short-lived access, refresh secure, MFA staff and step-up critical. No local credentials stored. Server authorization every resource by subject, action, location, role, assignment, ownership and consent. External supplier limited to assigned order; owner not bypass audit. Deny by default. Rate limit and request validation; no PII prompts in logs. Secrets Manager / local env ignored. Signed URLs short TTL scoped; scan MIME and content; quarantine until clean. Geometry workers sandbox no network by default; CPU/memory/time bounded. Reject zip traversal/bombs and oversized meshes. TLS, private subnets, storage encryption and key rotation, backups separate account/role where feasible. CORS allowlist; no debug in prod. Redact data in notifications, no vault details on lock screen.

Critical actions: release production, inventory adjustment/transfer above thresholds, refund, price override, cert revoke, grant admin. Step-up + optional dual approval (initiator != approver); approval binds exact input digest, expiry, reason and scope. Append-only audit actor/action/resource/timestamp/correlation/outcome; protect write/read roles, retention, alert anomalies. Review deletion rights vs legal retention, data export, consent per purpose (marketing, AI, photo, memory) and revocation. Privacy review by market before enabling. Public certificate endpoint returns minimal issuer/item/status not address/owner. OWASP MASVS/MASTG and ASVS/API security testing reference; PCI scope assessed with provider. SBOM and license review, dependency pinning, secret scans and vulnerability triage before release. No card PAN/CVV. Incident playbook: isolate, revoke tokens/keys, preserve evidence, assess notification obligations, restore, postmortem.

## Matriz de permisos (hito 100)
`roles.reference.json` es la referencia: `default: DENY`, sin comodines y cada concesión con un alcance explícito (`scopes`, vocabulario en `scopeVocabulary`). `tools/contracts/check_permissions.py` falla en CI si un permiso usado por la API, una herramienta o una pantalla no lo tiene ningún rol, si una pantalla pide un permiso que su rol no tiene, o si un rol junta autor y publicador de la biblioteca. El alcance es un requisito para el backend, que lo aplica por recurso y ubicación; la matriz no sustituye esa verificación.

Aprobación de diseño (1.3.0): `design.approve` lo tiene el diseñador, que también edita; por eso la regla es por acción y no por rol: el servidor rechaza que apruebe o devuelva una revisión quien la envió, y la aprobación queda ligada al digest de la revisión y al reporte DFM.
