# ADR-0003: Render 3D móvil — WebView + Three.js; Filament como alternativa
Estado: **aceptado** el 2026-11-25 (decisor: ian, propietario del producto). Cierra P0-04 del hito 000.

Contexto: la dirección inicial era "Filament candidato, comparación WebView", con la condición de no seleccionar sin benchmark (FPS, memoria, calidad óptica, batería).

## Decisión
La app móvil (Expo, ADR-0002) renderiza la vista previa GLB con **Three.js dentro de un WebView** (WebGL2). Filament nativo queda documentado como alternativa, no como camino principal.

El render sigue siendo solo una vista previa: la geometría técnica (BREP/malla) es independiente y no se deriva del render.

## Medición (Samsung Galaxy Z Flip 7, SM-F766B, Xclipse 950, pantalla 60 Hz)
| | WebView + Three.js | Filament nativo |
|---|---|---|
| Versión | aurea-render-bench 0.2.0, three r160, Chrome 157 WebView | aurea-render-bench-android 0.1.5, Filament 1.79.0 (gltfio ubershader) |
| base / vitrina / estrés (25 anillos) | 60,1 FPS, p95 16,7 ms | 60,1 FPS, p95 16,7 ms |
| Máximo sostenido en la rampa (p95 ≤ 1,1 × cadencia) | 2500 anillos, 5,24 M triángulos, 7500 draw calls (p95 17,2 ms) | 400 anillos, 435 k triángulos; a 900 p95 33,3 ms |
| Primer cuadro | 301 ms | 584 ms |
| Memoria | 61 MB heap JS (no incluye GPU ni proceso) | 347 MB PSS del proceso |
| Batería | sin cargar; 95 % → 94 % en 83 s | medido cargando (no comparable) |

Evidencia: `tools/render-bench/results/2026-11-25-zflip7-webview-threejs-v0.2.json` y `tools/render-bench/results/2026-11-25-zflip7-native-filament.json`.

## Justificación
- Para la carga real (un anillo, o decenas en vitrina) los dos caminos van a 60 FPS con margen amplio; la web tuvo más techo en esta prueba.
- Comparte código y materiales con el centro de mando web (Next.js) y se integra con Expo sin módulo nativo propio.
- Filament exigió compileSdk 37 / AGP 9.4.1 y mostró un fallo nativo en 1.79.0 (destruir `IBLPrefilterContext` liberaba la cámara de la vista: SIGSEGV en `FView::computeCameraInfo`; mitigado manteniendo el contexto vivo).

## Limitaciones y pendientes
- La calidad óptica no se midió con un criterio objetivo; falta revisión visual humana del oro y la gema.
- El techo bajo de Filament es probablemente por el ubershader de gltfio y el pipeline HDR + MSAA; no está verificado. Una prueba con materiales compilados (matc) podría cambiar la comparación.
- Una sola unidad, pantalla limitada a 60 Hz; no se midió térmica sostenida ni gama baja.
- Las escenas no son idénticas: la web dibuja la gema como malla aparte (3 draw calls por anillo) y usa clearcoat; el entorno y el tone mapping difieren.

## Revisión
Revisar si: falla el gate de rendimiento en un dispositivo objetivo de gama baja, la revisión visual rechaza la calidad óptica, o el WebView no soporta una función necesaria (p. ej., transmisión/refracción de gemas). Registrar decisión, medición, versión y responsable. No cambiar contratos sin migración.

Alternativa rechazada: seleccionar sin benchmark.
